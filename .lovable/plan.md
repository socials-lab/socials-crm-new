

## Plan: Auto-detect Graphic Designer role and show per-credit reward fields in AssignmentForm

### Problem
When adding a graphic designer to an engagement, the user must manually set up the per-credit reward model afterward via the EditAssignmentDialog. The AssignmentForm doesn't support the "per credit" cost model at all, so there's no way to configure Creative Boost rewards during the initial assignment.

### Solution
Enhance the `AssignmentForm` to:
1. Detect when the selected colleague has a "designer/grafik" position or when the user types a role like "Graphic Designer"
2. Add a "per_credit" cost model option (when the engagement has a Creative Boost service)
3. Show banner/video reward-per-credit fields when "per_credit" is selected
4. Save the rewards via the existing `setRewards()` mock data function after assignment creation

### Changes

**1. `src/components/forms/AssignmentForm.tsx`**
- Add `engagementServices` prop to check if this engagement has a Creative Boost service
- Add `per_credit` as a cost model option (visible only when CB service exists on the engagement)
- Add banner reward and video reward input fields (shown when `per_credit` is selected)
- Auto-switch cost model to `per_credit` when the selected colleague's position contains "design", "grafik", or "video"
- On submit, call `setRewards()` with the configured per-credit values and pass `engagement_service_id` pointing to the CB service

**2. `src/pages/Engagements.tsx`**
- Pass `engagementServices` (filtered for the current engagement) to the `AssignmentForm`
- Update `handleAssignmentSubmit` to also save Creative Boost rewards when the per-credit model is used
- Pass the Creative Boost `engagement_service_id` to the form so assignments link to the correct service

### Technical details
- The per-credit rewards are stored in frontend mock data (`creativeBoostRewardsMockData.ts`) via `setRewards(assignmentId, { bannerRewardPerCredit, videoRewardPerCredit })`
- Since the assignment ID is generated by Supabase on insert, the reward save needs to happen after the assignment is created (in the submit handler callback in Engagements.tsx, using the returned assignment ID)
- The form will submit with `cost_model: 'fixed_monthly'` and null costs to the DB (same pattern as EditAssignmentDialog), while the actual per-credit config lives in mock data
- Default values: 80 CZK/credit for banners, 80 CZK/credit for videos
